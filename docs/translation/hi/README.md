**Omega-Fuzz** एक स्थानीय टर्मिनल एप्लिकेशन है ([Textual](https://github.com/Textualize/textual) आधारित TUI + स्क्रिप्ट योग्य CLI) जो अधिकृत वातावरणों में — जैसे लैब, व्यक्तिगत मिरर या स्पष्ट रूप से सहमति प्राप्त परीक्षण — वेब सुरक्षा खोज और परीक्षण (HTTP fuzzing) करता है।

यह उपकरण `omega-` सूट का हिस्सा है और Clean Architecture में संरचित है — पूर्ण तकनीकी विवरण के लिए `docs/ARCHITECTURE.md` देखें।

## 1. दृष्टि और दायरा

### Omega-Fuzz क्या करता है

- स्पष्ट स्कोप (स्कीम, सबडोमेन, अनुमत/अवरोधित पथ, गहराई) द्वारा सीमित BFS से एकल लक्ष्य के दायरे की खोज करता है, बिना सुरक्षात्मक साधनों के कभी नहीं।
- प्रत्येक खोजे गए URL पर मिले query string पैरामीटर, HTTP हेडर और `GET` फ़ॉर्म पर सामान्य फ़ज़िंग करता है, और तीन प्रकार के हस्ताक्षर जाँचता है: गैर-विनाशकारी reflected XSS, सामान्य इंजेक्शन (प्रतिक्रिया में त्रुटि पहचान), तथा अनुपस्थित या गलत कॉन्फ़िगर किए गए सुरक्षा हेडर — [§5](#5-निष्पादित-सुरक्षा-परीक्षण) देखें।
- प्रत्येक विसंगति को 3 अक्षों (प्रभाव, शोषण योग्यता, दायरा) पर स्कोर करता है और `low`/`medium`/`high`/`critical` गंभीरता निकालता है, `(प्रकार, एंडपॉइंट, पैरामीटर)` के आधार पर डुप्लिकेट हटाते हुए सर्वोत्तम प्रमाण रखता है — [§6](#6-स्कोर-और-गंभीरता) देखें।
- समर्पित YAML फ़ाइल के माध्यम से प्रमाणीकरण (cookie, bearer token, लॉगिन फ़ॉर्म) समर्थित करता है; क्रेडेंशियल कभी भी कमांड लाइन में सादे पाठ में नहीं दिए जाते।
- परिणाम TUI (Textual) या स्क्रिप्ट योग्य CLI में दिखाता है, तीन निर्यातों के साथ (JSON, Markdown, HTML 5 थीम)।
- स्कैन इतिहास और findings को SQLite में स्थायी रूप से रखता है, साथ ही पुनः उपयोग योग्य पसंदीदा लक्ष्यों की सूची भी।
- किसी भी आक्रामक, विस्तारित, या TLS सत्यापन अक्षम वाले स्कैन से पहले स्पष्ट पुष्टि (सबसे संवेदनशील मामलों में सटीक वाक्यांश) माँगता है।

### Omega-Fuzz क्या नहीं करता

- JSON बॉडी फ़ज़िंग — कोड मौजूद है (`plugins/fuzzers/json_body_fuzzer.py`) पर जुड़ा नहीं है (HTML/BFS खोज कोई JSON API स्कीमा या उपयोगी टेम्पलेट स्रोत नहीं बनाती)।
- `POST`/`PUT`/`DELETE` फ़ॉर्म फ़ज़िंग — स्वचालित पाइपलाइन से जानबूझकर बाहर रखा गया (लक्ष्य पर अनचाहे लेखन का जोखिम); केवल `GET` फ़ॉर्म परीक्षित होते हैं।
- व्यावसायिक तर्क परीक्षण (IDOR, प्राधिकरण नियंत्रण, वर्कफ़्लो विघटन) — कोड मौजूद है (`plugins/logic_tests/`) पर स्वचालित पाइपलाइन के बाहर है, केवल अलग से लागू किया जा सकता है और मानक स्कैन द्वारा कभी ट्रिगर नहीं होता।
- बहु-लक्ष्य समानांतर स्कैन — प्रति स्कैन एक लक्ष्य।
- इतिहास स्क्रीन से पुनः चलाना, तुलना या निर्यात — केवल `Scan` और `Finding` संग्रहीत होते हैं (पूर्ण प्रभावी कॉन्फ़िगरेशन या अनुरोध नहीं); इतिहास से पुनः चलाना या निर्यात डेटा बनाएगा। स्क्रीन इसे समझाती है, चुपचाप सुविधा प्रदान नहीं करती।
- क्लाइंट-साइड JavaScript रेंडरिंग (पृष्ठ उसी रूप में लिया जाता है जैसा सर्वर देता है, headless ब्राउज़र में निष्पादित नहीं होता)।
- वेब डैशबोर्ड।

## 2. इंस्टॉलेशन

### पूर्वापेक्षाएँ

- Python 3.10+
- निर्भरताओं के लिए इंटरनेट कनेक्शन
- TUI के लिए: हेडर आइकन के लिए टर्मिनल में [Nerd Font](https://www.nerdfonts.com/) इंस्टॉल होना चाहिए — अन्यथा वह वर्ण खाली वर्ग के रूप में दिखेगा (emoji जैसी ही सीमा, पर टर्मिनल उपयोगकर्ताओं में कहीं अधिक सामान्य)। फ़ॉन्ट की अनुपस्थिति कार्यप्रणाली को प्रभावित नहीं करती; केवल दिखावटी है।

### इंस्टॉलेशन

```bash
[ -d omega-fuzz ] && echo "ℹ️ यहाँ पहले से निकाला गया है, चरण छोड़ा जा रहा है।" || tar -xzf omega-fuzz.tar.gz
cd omega-fuzz/
chmod +x install.sh
./install.sh
```

`install.sh`:

1. `.venv` वर्चुअल वातावरण बनाता है, यदि पहले से मौजूद नहीं है।
2. निर्भरताएँ इंस्टॉल करता है (`vendor/omega-lib/`, फिर `pip install -e .`; `pyproject.toml` एकमात्र सत्य का स्रोत बना रहता है)।
3. `omega-fuzz.sh` और `install.sh` को निष्पादन योग्य बनाता है।
4. `~/.bashrc` और `~/.zshrc` में `fuzz` उपनाम जोड़ता है (पहले से होने पर डुप्लिकेट नहीं)।

### निर्भरताएँ

`pyproject.toml` में घोषित (कोई `requirements.txt` नहीं):

- `omega-lib`: सूट की साझा लाइब्रेरी (निर्यात थीम, टर्मिनल पहचान, `ConfidenceLevel`) — `vendor/omega-lib/` में वेंडर की गई
- `httpx`: असिंक्रोनस HTTP अनुरोध (खोज + फ़ज़िंग), प्रतिक्रिया स्ट्रीमिंग (लक्ष्य द्वारा दी गई कई GB की फ़ाइल पर भी पूरी प्रतिक्रिया कभी मेमोरी में बफ़र नहीं होती)
- `beautifulsoup4` + `lxml`: URL और HTML फ़ॉर्म निकालना
- `jinja2`: HTML निर्यात के लिए टेम्पलेटिंग
- `textual`: TUI इंटरफ़ेस, थीम, टर्मिनल के लिए स्वतः अनुकूलन
- `pyyaml`: `--auth-config` फ़ाइल लोड करना
- विकास निर्भरताएँ (`pip install -e ".[dev]"`): `pytest`, `pytest-asyncio`, `pytest-cov`, `pytest-httpserver`, `ruff`, `mypy`, `import-linter`

## 3. उपयोग

### इंटरैक्टिव मोड (TUI)

दैनिक उपयोग के लिए अनुशंसित — बिना तर्क चलाया जाता है:

```bash
./omega-fuzz.sh
```

यदि उपनाम बनाया गया है, तो टर्मिनल में केवल `fuzz` टाइप करें:

```bash
fuzz
```

प्रवाह: स्टार्ट स्क्रीन (कुंजी या क्लिक से बंद) → मुख्य मेनू (स्कैन करें / लक्ष्य / सेटिंग्स / इतिहास / सहायता) → लक्ष्य दर्ज करना (पूर्ण URL, `http://`/`https://` स्कीम अनिवार्य), प्रीसेट या मैन्युअल कॉन्फ़िगरेशन (स्कोप + आक्रामकता), वैकल्पिक प्रमाणीकरण, TLS सत्यापन, सीमाओं का ओवरराइड → समीक्षा स्क्रीन (सामान्य पुष्टि, या संवेदनशील मामलों में सटीक वाक्यांश `OUI-J-AI-L-AUTORISATION`) → स्कैन (अनिश्चित प्रगति संकेतक, किसी भी समय **रोकें** बटन) → परिणाम (findings, निर्यात) → इतिहास (पिछले स्कैन का विवरण और संबंधित findings) तथा मुख्य मेनू से पसंदीदा लक्ष्य। टर्मिनल अनुकूलन (रंग, आकार, संरचनात्मक अवनति) स्वतः होता है।

#### कीबोर्ड शॉर्टकट

| कुंजी | कार्य |
|---|---|
| `↑` / `↓` | स्क्रीन के तत्वों के बीच नेविगेट |
| `Tab` / `Shift+Tab` | फ़ॉर्म के फ़ील्ड के बीच नेविगेट |
| `Esc` | पिछली स्क्रीन पर वापस (स्टार्ट स्क्रीन पर निकास पुष्टि) |
| `t` | अगली थीम (बिना पुष्टि तुरंत लागू) |
| `r` | टर्मिनल पहचान ताज़ा करें |
| `a` | सहायता दिखाएँ (शामिल प्रीसेट की तालिका) |
| `q` | बाहर निकलें (पुष्टि के साथ) |
| `Ctrl+P` | कमांड पैलेट (Theme, बाहर निकलें, स्क्रीनशॉट) |

### इंटरफ़ेस की भाषाएँ

इंटरफ़ेस 17 भाषाओं में उपलब्ध है: फ़्रेंच, अंग्रेज़ी, स्पेनिश, पुर्तगाली (ब्राज़ील), इतालवी, जर्मन, डच, पोलिश, रूसी, सरलीकृत चीनी, वियतनामी, थाई, इंडोनेशियाई, जापानी, कोरियाई, हिन्दी और अरबी। भाषा सेटिंग्स («भाषा / Language») में चुनी जाती है और इंटरफ़ेस पुनरारंभ होने पर लागू होती है; चर `OMEGA_FUZZ_LANG` (उदाहरण `OMEGA_FUZZ_LANG=en ./omega-fuzz.sh`) एक सत्र के लिए भाषा लागू करता है। omega-suite से चलाने पर omega-fuzz सूट की भाषा लेता है। Linux टेक्स्ट कंसोल (TTY) पर, गैर-लैटिन लिपि वाली भाषाएँ सत्र के दौरान अंग्रेज़ी में दिखती हैं। कमांड लाइन फ़्रेंच में रहती है।

### स्क्रिप्ट मोड (CLI)

```bash
# तैयार प्रीसेट के साथ स्कैन
./omega-fuzz.sh scan --target https://example.com --preset prod-safe

# स्कोप + आक्रामकता का मैन्युअल संयोजन (प्रीसेट के बिना)
./omega-fuzz.sh scan --target https://example.com --scope-profile standard --aggressiveness standard

# प्रमाणीकरण के साथ (YAML फ़ाइल, कमांड लाइन में कभी सादे क्रेडेंशियल नहीं)
./omega-fuzz.sh scan --target https://example.com --preset staging-full --auth-config auth.yaml

# Dry-run: प्रभावी कॉन्फ़िगरेशन और अनुमानित योजना, कोई अनुरोध नहीं भेजा जाता
./omega-fuzz.sh scan --target https://example.com --preset prod-safe --dry-run

# लक्षित निर्यात (फ़ोल्डर, प्रारूप, HTML थीम)
./omega-fuzz.sh scan --target https://example.com --preset prod-safe \
    --output-dir ./rapports --format html --export-theme omega-neon
```

`scan` के विकल्प:

| विकल्प | डिफ़ॉल्ट | प्रभाव |
|---|---|---|
| `--target` | *(आवश्यक)* | लक्ष्य URL, `http://`/`https://` स्कीम अनिवार्य (कभी स्वतः पूर्ण नहीं) |
| `--preset` | — | तैयार प्रीसेट ([§4](#4-स्कोप-प्रोफ़ाइल-और-प्रीसेट) देखें) |
| `--scope-profile` | — | स्कोप प्रोफ़ाइल, `--aggressiveness` के साथ जोड़ें, `--preset` के बिना |
| `--aggressiveness` | — | आक्रामकता स्तर, `--scope-profile` के साथ जोड़ें, `--preset` के बिना |
| `--auth-config` | — | प्रमाणीकरण YAML फ़ाइल |
| `--insecure-tls` | अक्षम | TLS सत्यापन अक्षम करता है (मजबूत पुष्टि ट्रिगर करता है) |
| `--max-duration` | *(प्रोफ़ाइल से)* | अधिकतम अवधि (सेकंड) ओवरराइड |
| `--max-requests` | *(प्रोफ़ाइल से)* | अधिकतम अनुरोध संख्या ओवरराइड |
| `--max-tests` | *(प्रोफ़ाइल से)* | अधिकतम परीक्षण संख्या ओवरराइड |
| `--max-concurrent` | *(प्रोफ़ाइल से)* | अधिकतम समानांतरता ओवरराइड |
| `--dry-run` | अक्षम | प्रभावी कॉन्फ़िगरेशन और अनुमानित योजना दिखाता है, कोई अनुरोध नहीं भेजता |
| `--output-dir` | `var/exports/` | निर्यात रिपोर्ट फ़ोल्डर, नाम `<preset>-<टाइमस्टैम्प>.<एक्सटेंशन>` (सेटिंग्स में बदला जा सकता है) |
| `--format` | `all` | `json`, `markdown`, `html` या `all` |
| `--export-theme` | `omega-base` | निर्यात HTML रिपोर्ट की थीम (json/markdown पर प्रभाव नहीं) |

CLI में `history`/`show` सबकमांड नहीं है: इतिहास और पसंदीदा लक्ष्य केवल TUI से देखे जा सकते हैं।

यदि `install.sh` ने उपनाम बनाया है, तो `fuzz scan ...` टर्मिनल में कहीं से भी, `./omega-fuzz.sh` उपसर्ग के बिना काम करता है।

## 4. स्कोप प्रोफ़ाइल और प्रीसेट

### स्कोप प्रोफ़ाइल

| प्रोफ़ाइल | मोड | अधिकतम गहराई | प्रतिबंध |
|---|---|---|---|
| `strict` | सटीक लक्ष्य | 1 | `/health`, `/ready`, `/metrics`, `/favicon.ico`, `/robots.txt` अवरुद्ध |
| `standard` | + सबडोमेन | 2 | सामान्य स्थिर सबडोमेन, तकनीकी पथ और एसेट (छवि/css/js/फ़ॉन्ट) अवरुद्ध |
| `large` | + सबडोमेन | 4 | केवल तकनीकी पथ और एसेट (संग्रह/PDF सहित) अवरुद्ध |
| `api` | सटीक लक्ष्य | 3 | `/api`, `/v1`, `/v2` तक सीमित; दस्तावेज़ीकरण और एसेट अवरुद्ध |
| `custom` | + सबडोमेन | 3 | कोई डिफ़ॉल्ट प्रतिबंध नहीं — मैन्युअल कॉन्फ़िगरेशन का प्रारंभिक बिंदु |

चुने गए किसी भी प्रोफ़ाइल के बावजूद, बाइनरी/बड़ी फ़ाइल एक्सटेंशन की सूची (`.iso`, `.zip`, `.exe`, `.mp4` आदि) क्रॉल और फ़ज़िंग से **हमेशा** बाहर रखी जाती है, `custom` में भी — इस प्रकार की फ़ाइल का लिंक वास्तविक HTTP अनुरोध से कभी नहीं लिया जाता, ताकि डाउनलोड फ़ोल्डर स्कैन को कई मिनट धीमा न करे।

### आक्रामकता स्तर

`doux` · `standard` · `agressif` · `violent` — प्रत्येक स्तर की अपनी आधारभूत सीमाएँ हैं (अवधि, अनुरोध, परीक्षण, गहराई, समानांतरता), जिन्हें प्रीसेट होने पर ओवरराइड करता है।

### तैयार प्रीसेट

| प्रीसेट | स्कोप | आक्रामकता | अधिकतम समय | अधिकतम अनुरोध | अधिकतम परीक्षण | अधिकतम गहराई | मजबूत पुष्टि |
|---|---|---|---|---|---|---|---|
| `prod-safe` | strict | doux | 300 सेकंड | 1,000 | 500 | 1 | नहीं |
| `staging-full` | standard | standard | 1,800 सेकंड | 20,000 | 10,000 | 2 | नहीं |
| `lab-deep` | large | agressif | 3,600 सेकंड | 100,000 | 50,000 | 4 | नहीं |
| `lab-extreme` | large | violent | 7,200 सेकंड | 500,000 | 250,000 | 5 | **हाँ** |
| `api-hardened` | api | agressif | 1,800 सेकंड | 50,000 | 25,000 | 3 | नहीं |

पुष्टि होने तक स्कैन अवरुद्ध रहता है। **मजबूत** पुष्टि (सटीक वाक्यांश `OUI-J-AI-L-AUTORISATION` टाइप करना) तब आवश्यक है जब इन तीन कारकों में से कोई एक मौजूद हो: आक्रामकता `violent`, प्रीसेट `lab-extreme`, या TLS सत्यापन अक्षम (`--insecure-tls`) — इन तीन कारकों में से किसी के बिना असामान्य संयोजन पर सामान्य हाँ/नहीं पुष्टि।

## 5. निष्पादित सुरक्षा परीक्षण

स्वचालित पाइपलाइन, स्कोप में खोजे गए प्रत्येक URL (और वहाँ मिले प्रत्येक `GET` फ़ॉर्म) पर:

| परीक्षण | ट्रिगर | क्या जाँचा जाता है |
|---|---|---|
| सामान्य पैरामीटर फ़ज़िंग | हर query string पैरामीटर | सीमा/दूषित मानों पर लक्ष्य का व्यवहार |
| हेडर फ़ज़िंग | प्रति URL एक बार, 4 स्थिर हेडर (`User-Agent`, `Referer`, `X-Forwarded-For`, `Accept-Language`) | हेडर में सीमा/दूषित मानों पर लक्ष्य का व्यवहार |
| फ़ॉर्म फ़ज़िंग (केवल `GET`) | स्कोप में खोजा गया हर `GET` फ़ॉर्म फ़ील्ड | फ़ॉर्म फ़ील्ड में सीमा/दूषित मानों पर लक्ष्य का व्यवहार |
| Reflected XSS | हर query string पैरामीटर | प्रतिक्रिया में पेलोड का अनफ़िल्टर्ड परावर्तन (गैर-विनाशकारी) |
| सामान्य इंजेक्शन | हर query string पैरामीटर | इंजेक्शन पेलोड के जवाब में सर्वर त्रुटि का पता (विशिष्ट SQL/NoSQL फ़िंगरप्रिंटिंग नहीं) |
| सुरक्षा हेडर | प्रति URL एक बार | प्रतिक्रिया में अनुपस्थित या गलत कॉन्फ़िगर सुरक्षा हेडर |

पहले तीन परीक्षण (सामान्य पैरामीटर/हेडर/फ़ॉर्म फ़ज़िंग) **बिना पहचान** वाला म्यूटेशन इंजन हैं — वे कभी सीधे `Finding` नहीं बनाते; केवल सामने आई सर्वर त्रुटियाँ (5xx) संबंधित `Test` में गिनी जाती हैं। findings केवल हस्ताक्षर (XSS, इंजेक्शन, सुरक्षा हेडर) से बनते हैं।

## 6. स्कोर और गंभीरता

प्रत्येक पहचानी गई विसंगति को 3 अक्षों (`impact`, `exploitability`, `scope`, प्रत्येक 1–5) पर अवलोकन की प्रकृति के अनुसार स्कोर किया जाता है — मैपिंग जानबूझकर **रूढ़िवादी** है (रेंज का निचला भाग, इस स्वचालित चरण में कोई मानव पुष्टि नहीं):

| कच्चा स्कोर (3 अक्षों का योग) | गंभीरता |
|---|---|
| ≥ 13 | `critical` |
| ≥ 10 | `high` |
| ≥ 7 | `medium` |
| < 7 | `low` |

मैन्युअल समायोजन (`severity_override`) संभव है पर हमेशा स्पष्ट औचित्य माँगता है। समतुल्य findings (वही प्रकार, एंडपॉइंट और पैरामीटर) डीडुप्लिकेट किए जाते हैं, सर्वोत्तम उपलब्ध प्रमाण रखते हुए (विश्वास स्तर `omega_lib.core.confidence.ConfidenceLevel`, बराबरी पर कच्चा स्कोर)।

## 7. प्रमाणीकरण

समर्पित YAML फ़ाइल (`--auth-config`), कमांड लाइन में कभी सादे क्रेडेंशियल नहीं:

| मोड | प्रभाव |
|---|---|
| `none` | कोई प्रमाणीकरण नहीं (डिफ़ॉल्ट) |
| `cookie` | सत्र कुकी सीधे दी जाती है |
| `bearer_token` | `Authorization: Bearer ...` टोकन |
| `login_form` | फ़ॉर्म द्वारा प्रमाणीकरण (लॉगिन URL, उपयोगकर्ता/पासवर्ड फ़ील्ड) |

## 8. आर्किटेक्चर

Omega-Fuzz **Clean Architecture** (domain / application / infrastructure / interfaces / ports / core / app / plugins) में संरचित है, `omega-` सूट के टेम्पलेट (`omega-check`/`omega-deep`/`omega-fold` देखें) के अनुरूप है और प्रत्येक परिवर्तन पर `import-linter` द्वारा सत्यापित होता है। पूर्ण विवरण **`docs/ARCHITECTURE.md`** में है।

अति संक्षिप्त अवलोकन:

```text
src/omega_fuzz/
├── domain/          शुद्ध डोमेन तर्क (लक्ष्य/स्कोप, अनुरोध, परीक्षण, findings, प्रोफ़ाइल, रिपोर्ट...)
├── application/     उपयोग मामले (commands/queries) और ऑर्केस्ट्रेटर (खोज, स्कैन, रिपोर्ट, सीमाएँ)
├── ports/           एप्लिकेशन द्वारा अपेक्षित अनुबंध (http_client, repositories, exporters...)
├── infrastructure/  ठोस कार्यान्वयन (httpx, BeautifulSoup, SQLite, Jinja2 exporter — Textual यहाँ नहीं)
├── interfaces/      tui/ (Textual) और cli/ (स्क्रिप्ट योग्य), कड़ी कार्यात्मक समता
├── plugins/         फ़ज़र और हस्ताक्षर (शुद्ध फ़ंक्शन, कभी सीधा नेटवर्क एक्सेस नहीं)
├── app/             संयोजन (Container, composition root, जीवनचक्र)
└── core/            साझा शब्दावली, त्रुटियाँ, स्थिरांक
```

डिज़ाइन नियम:

- `plugins/fuzzers/` और `plugins/signatures/`: परीक्षण योजना (`Test` + `ScanRequest`) बनाने वाले शुद्ध फ़ंक्शन, कभी `HttpClient` को नहीं छूते।
- `infrastructure/network/`: नेटवर्क करता है (`httpx`, मेमोरी-सीमित स्ट्रीमिंग), कभी निर्णय नहीं लेता।
- `infrastructure/analyzers/`: पहले से प्राप्त प्रतिक्रिया पढ़ता है, संरचित `Observation` बनाता है, स्कोर कभी दोबारा नहीं गिनता।
- `interfaces/`: केवल दिखाता है, व्यावसायिक तर्क नहीं रखता।

## 9. निर्यात

Markdown और HTML रिपोर्ट सेटिंग्स में चुनी गई भाषा («एक्सपोर्ट की भाषा», डिफ़ॉल्ट इंटरफ़ेस की भाषा) में लिखी जाती हैं; JSON डेटा बना रहता है, अनुवादित नहीं होता। रिपोर्ट डिफ़ॉल्ट रूप से `var/exports/` में बनती हैं (रनटाइम पथ प्रोजेक्ट फ़ोल्डर पर आधारित, `$OMEGA_FUZZ_VAR_DIR` से ओवरराइड, सेटिंग्स स्क्रीन से भी), या निर्दिष्ट पथ (`--output-dir`) पर। फ़ाइल नाम सपाट, बिना सबफ़ोल्डर: `<preset>-<टाइमस्टैम्प>.<एक्सटेंशन>` (उदाहरण `prod-safe-2026-09-01_14-30-22.html`)।

### JSON, सत्य का स्रोत

रिपोर्ट की पूर्ण संरचना (प्रभावी कॉन्फ़िगरेशन, आँकड़े, परीक्षण, findings), सख्ती से JSON-serializable।

### Markdown, संक्षिप्त मानव-पठनीय रिपोर्ट

टर्मिनल के बाहर पठनीय, ANSI कोड रहित।

### HTML, स्वतंत्र वेब रिपोर्ट

चुनने के लिए 5 थीम (CLI में `--export-theme`, TUI में चयनकर्ता): `omega-base`, `omega-burn`, `omega-neon`, `light-basic`, `light-alt`।

## 10. इतिहास और पसंदीदा लक्ष्य

प्रत्येक स्कैन findings के साथ SQLite (`var/db/omega-fuzz.db`) में संग्रहीत होता है और TUI की इतिहास स्क्रीन से देखा जा सकता है। केवल `Scan` और `Finding` संग्रहीत होते हैं — पूर्ण प्रभावी कॉन्फ़िगरेशन या विस्तृत अनुरोध नहीं — इसलिए इस स्क्रीन से पुनः चलाना, तुलना या नया निर्यात नहीं है (स्क्रीन इसे समझाती है, डेटा नहीं बनाती)।

**लक्ष्य** स्क्रीन पसंदीदा सूची (सामान्यीकृत URL, `var/targets.json`) रखती है, नए स्कैन के लक्ष्य फ़ील्ड को सीधे भरने के लिए पुनः उपयोग योग्य।

## 11. स्क्रीनशॉट

कमांड पैलेट (`Ctrl+P`) की **स्क्रीनशॉट** कमांड: वर्तमान TUI स्क्रीन का SVG डिफ़ॉल्ट रूप से `var/screenshots/` में सहेजती है, सेटिंग्स स्क्रीन से बदला जा सकता है (निर्यात फ़ोल्डर की तरह)। सेटिंग्स में समर्पित सफ़ाई उपलब्ध है।

## 12. टर्मिनल संगतता

TUI (Textual) टर्मिनल क्षमताएँ (एमुलेटर, आकार) स्वतः पहचानता है और उसके अनुसार संरचनात्मक स्टाइलशीट (`complete`/`standard`/`reduced`/`mono`) अनुकूलित करता है, बिना मैन्युअल फ़्लैग। CLI हमेशा सादा पाठ रहता है, टर्मिनल से स्वतंत्र। यह नीति पूरे `omega-` सूट द्वारा साझा है (`omega-lib`, `terminal/policies.py`)।

### पहचाने गए एमुलेटर के अनुसार प्रोफ़ाइल

| एमुलेटर | प्रारंभिक प्रोफ़ाइल |
|---|---|
| Ghostty, Alacritty, WezTerm, Kitty | `complete` |
| Konsole, GNOME Terminal, Terminator, Xfce4 Terminal | `standard` |
| xterm, urxvt, आधुनिक SSH | `reduced` |
| Linux TTY, पुराना SSH | `mono` |
| अज्ञात एमुलेटर | `reduced` (डिफ़ॉल्ट फ़ॉलबैक) |

### टर्मिनल आकार के अनुसार प्रोफ़ाइल

| न्यूनतम आकार (कॉलम × पंक्तियाँ) | प्रोफ़ाइल सीमा |
|---|---|
| 120 × 32 | `complete` |
| 100 × 28 | `standard` |
| 80 × 24 | `reduced` |
| इससे कम | `mono` |

अंतिम प्रोफ़ाइल दोनों में **अधिक प्रतिबंधक** है (एमुलेटर और आकार) — `r` कुंजी से सीधे ताज़ा किया जा सकता है।

```bash
source .venv/bin/activate
lint-imports        # Dependency Rule (6 अनुबंध) सत्यापित करता है
pytest -q           # 344 परीक्षण

```

संरचना: `tests/unit/` (डोमेन और एप्लिकेशन, वास्तविक I/O नहीं), `tests/integration/` (`tmp_path` द्वारा वास्तविक फ़ाइलसिस्टम, `pytest-httpserver` नकली HTTP सर्वर, वास्तविक SQLite डेटाबेस, एंड-टू-एंड CLI), `tests/tui/` (`Pilot` द्वारा नेविगेशन, संरचनात्मक जाँच — स्वचालित दृश्य सत्यापन का दावा नहीं)।
